## Verification Sections

### A. Database Architecture — PASS
- **Dual-Mode Architecture**: The application operates in dual mode:
  - **Local Development / Dockerless**: Self-contained in-memory database store (`src/lib/db-store.ts`) with automated file persistence via `.elms360_dev_db.json`. Changes made via any UI action persist across Next.js hot reloads and server restarts without requiring local Docker or Supabase CLI daemons.
  - **Cloud Production**: The moment `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are populated in `.env.local`, the application automatically cuts over to live PostgreSQL 15 on Supabase.
- **Relational Integrity**: 29 database tables, triggers, sequences, and stored procedures (`process_approval_action`, `submit_leave_request`, `calculate_working_days`) implemented across 4 migration scripts.
- **Reference**: Detailed architectural documentation available in [ARCHITECTURE.md](file:///Users/ananda/Downloads/EMPLOYEE%20LEAVE/elms360/ARCHITECTURE.md).

### B. Date Engine — PASS
- **Timezone-Safe Calendar Engine**: Built `src/lib/date-utils.ts` utilizing Tomohiko Sakamoto's algorithm for day-of-week calculation (`0=Sunday` to `6=Saturday`).
- **Zero Timezone Drift**: Completely eliminated `new Date().getDay()` timezone offsets (e.g. UTC midnight shifting by -5:30 for Asia/Kolkata).
- **Working Day Calculator**: Accurately calculates business days, weekly offs (5-day Sat/Sun or 6-day Sun-only), statutory holidays, and half-day multipliers (0.5).
- **Automated Test Suite**: 25 dedicated unit tests passing in `src/lib/__tests__/date-utils.test.ts`.

### C. Button Functionality — PASS

### D. Employee Workflow — PASS
- **Leave Application**: Form validation via React Hook Form and Zod with live day calculation and working day breakdown preview (`/employee/apply-leave`).
- **Self-Service Tracking**: Real-time view of personal applications, status badges, balance reservations, and vertical approval timelines (`/employee/my-leaves`).
- **Withdrawal & Cancellation**: One-click withdrawal of pending requests and cancellation workflows for approved requests with balance restoration.
- **Balance & Calendar**: Entitlement cards, accrued days, pending reservations, and department holiday calendar view.

### E. Manager Workflow — PASS
- **Pending Approvals Queue**: Real-time listing of applications submitted by direct reports (`/manager/approvals`).
- **Action Triggers**: Dedicated modals for **Approve** (with optional remarks), **Reject** (with mandatory reason validation), and **Request Clarification** (with employee question prompt).
- **Approval Delegation**: Temporary delegation builder to reassign approval authority to peer managers during out-of-office periods.
- **Team Calendar & Directory**: Department availability calendar to prevent understaffing collisions.

### F. HR Workflow — PASS
- **Policy Management**: Author and version annual allowances, carry-forward caps, accrual schedules, and probation eligibility (`/hr/leave-policies`).
- **Leave Balances & Ledger**: Manual balance adjustment with audit trail, balance ledger inspection, and CSV export (`/hr/leave-balances`).
- **Employee & Department Directory**: Employee profile onboarding, role assignments, department head configurations (`/hr/employees`).
- **Statutory Holidays & Schedules**: Holiday calendar management with bulk CSV import and work schedule templates (`/hr/holidays`, `/hr/work-schedules`).
- **Executive Analytics & Reporting**: Interactive Recharts dashboards for utilization, sick leave trends, balance liability, and aging analysis (`/hr/reports`).

### G. Realtime Infrastructure — PASS
- **WebSocket Synchronization**: `useRealtimeNotifications` hook with automatic fallback and reconnection logic.
- **Private Channel Scoping**: Listens on `private:employee:{employeeId}` for instant push notifications upon approval actions.
- **TanStack Query Invalidation**: Automatically refreshes notifications and dashboard badge counters without polling loops.

### H. Security & Compliance — PASS
- **Credential Hardening**: Plaintext evaluation passwords permanently redacted from public repository documentation; migrated to `.env.local.example` with `DEMO_PASSWORD`.
- **Row-Level Security**: 100% of public tables guarded with RLS policies (`003_rls_policies.sql`) preventing ID tampering or cross-tenant leakage.
- **Tamper-Evident Audit Logging**: System actions, approvals, policy changes, and balance modifications logged to `audit_logs` and `leave_balance_ledger`.
- **Idempotency Protection**: Idempotency keys enforced on approval actions and ledger transactions to eliminate duplicate deductions under network retries.
